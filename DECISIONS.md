# Решения

Все решения проекта: что решили, почему и кто. «Владелец» — автор проекта, «техлид» — технический лидер. Если решение расходится с исходным техзаданием, это отмечено.

## 2026-10-29 — интервью и план этапа 1

### D-001. Моды пишем как нативные моды Horizon (`.hnmod`), не WASM
- **Решение:** и Kiln, и таймер — нативные моды Horizon: Rust-код, который лаунчер встраивает в игру через horizon-mixins, на стабильных hook points (`crates/horizon-client/src/game/native_hooks.rs`).
- **Почему:** Horizon удаляет WASM-моды целиком: issues [#3350](https://github.com/horizon-rust/horizon/issues/3350), [#3351](https://github.com/horizon-rust/horizon/issues/3351), [#3353](https://github.com/horizon-rust/horizon/issues/3353), [#3371](https://github.com/horizon-rust/horizon/issues/3371), в ROADMAP.md: «then the WebAssembly runtime is removed». Официальные Zoom, Keystrokes, FPS Counter и Minimap уже нативные (2.0.0 от 2026-10-29). К тому же API песочницы (HUD-текст, чат, позиция игрока) слишком узок для Java-модов: нет мира, сущностей, рендера, экранов, сети.
- **Кто:** техлид, владелец подтвердил вместе с планом.
- **Расхождение с ТЗ:** ТЗ описывало WASM-API (`horizon:mods`, capabilities, хуки `tick/frame/command/chat`, `cargo horizon-mod test`). Для модов с кодом всё это больше неприменимо. По правилу «верь документации» план перестроен.

### D-002. Ограничение №1 переформулировано
- **Было:** мод работает в официальной сборке у любого игрока, через официальный Mod API.
- **Стало:** только официальные механизмы Horizon — нативные моды через лаунчер, на стабильных hook points; без форков и без правок исходников Horizon. Ограничение №2 (форк только по решению владельца) не меняется.
- **Почему:** без пересборки игры Horizon скоро не будет запускать никакие моды с кодом (D-001). Нативный мод игрок ставит из лаунчера; лаунчер один раз собирает игру (20–30 минут, с предупреждением) в отдельный инстанс «Native mods».
- **Кто:** техлид предложил, владелец подтвердил вместе с планом.

### D-005. Порядок: сначала Kiln, потом таймер как Java-мод через Kiln
- **Решение:** таймер пишем как обычный Java-мод (jar) и запускаем в Horizon через Kiln. Это первая демонстрация, что Kiln работает. Отдельного таймера на Rust не делаем.
- **Почему:** так хочет владелец: первый мод проекта сразу показывает его суть.
- **Цена:** таймер появится вместе с Kiln — примерно через 2 недели, а не через 3 дня. Если Kiln застрянет, не будет и таймера. техлид рекомендовал обратный порядок (сначала Rust-таймер); решение владельца.
- **Расхождение с ТЗ:** ТЗ говорило «саму прослойку в этой задаче не делаем». Владелец изменил это решение.

### D-006. Таймер — настоящий Fabric-мод без Mixin
- Один и тот же jar работает в Java Minecraft 26.3 с Fabric и в Horizon через Kiln. Java-версия служит эталоном поведения: Kiln работает, если в Horizon таймер ведёт себя так же.
- Без Mixin: поддержка Mixin — самая трудная часть Kiln (этап 4 видения).
- **Кто:** техлид (план), владелец принял план.

### D-007. Как Kiln выполняет Java — решает спайк
- Кандидаты: (1) настоящая JVM внутри игры через JNI; (2) свой интерпретатор Java-байткода на Rust; (3) компилятор jar → Rust-код, который лаунчер собирает как нативный мод.
- Спайк начинаем с (1): быстрее всего к «работает», рефлексия и библиотеки Майнкрафта (Gson, Guava) работают как есть, Java у игрока уже есть (лаунчер Horizon ставит её для подготовки файлов). Запасной — (2). Вариант (3) можно добавить позже как ускорение.
- **Кто:** техлид (план), владелец принял план.

### D-008. Достижения читаем из состояния игры
- В стабильных hook points нет ни хука на достижения, ни хука на входящий чат. Kiln раз в тик читает прогресс достижений игрока прямо в игре (`Game.adv`): точные ID, любой язык, работает и со скрытым чатом, и с выключенным `show_advancement_messages`.
- **Риск:** обновление Horizon может переименовать внутренние поля; тогда мод перестанет собираться, пока не выйдет правка. Ловим проверкой на свежем Nightly (`native.py check --horizon latest`).
- **Кто:** владелец, по рекомендации техлид.
- **Расхождение с ТЗ:** ТЗ предлагало распознавать сообщения о достижениях в чате.

### D-012. IGT считаем как SpeedRunIGT
- IGT — реальное время без пауз и экранов загрузки, как в SpeedRunIGT ([RedLime/SpeedRunIGT](https://github.com/RedLime/SpeedRunIGT), MIT) — главном Java-таймере спидран-сообщества. SpeedRunIGT — образец поведения; его логику можно заимствовать с указанием авторства (MIT), но код целиком не переносится: около 50 Mixin-классов, последняя версия для 1.19.4.
- **Кто:** владелец («найти готовый таймер и сделать похоже»).
- **Расхождение с ТЗ:** ТЗ предлагало IGT = тики × 50 мс и запрещало копировать код SpeedRunIGT. Тики при лагах выпадают, и IGT отставал бы от реального времени.

### D-015. Устройство репозитория
- Монорепозиторий. `kiln/` — нативный бандл (`kiln/mixins/kiln/`); его `Cargo.toml` делает `runtime.rs` библиотекой для `cargo test`, как у официальных модов.
- horizon-bridge будет модулем бандла, а не отдельным крейтом: нативные модули не могут подключать внешние крейты и другие файлы (`mod x;` и `include!` запрещены).
- Инструменты Horizon (`horizon-mods` с `native/tools/native.py`, `horizon-mixins`, шаблон) клонируются в `.deps/` и не попадают в git. `native.py` видит наш мод через символическую ссылку `.deps/horizon-mods/native/kiln`.
- **Кто:** техлид.

### D-016. Kiln собирается на Nightly 4baa571, hook points v1
- Тот же коммит, что у официальных модов. Пока используем только hook points v1; лаунчер соберёт мод на любой сборке Horizon, где они есть.
- **Кто:** техлид.

### D-018. Java запускается отдельным процессом (утверждено владельцем 2026-10-29)
- **Находка спайка:** в `horizon-client` стоит `#![forbid(unsafe_code)]`. Модули нативного мода встраиваются в этот крейт, а `forbid` не снимается. Без `unsafe` нельзя ни `dlopen`, ни JNI, поэтому JVM внутри процесса игры (D-007, вариант 1) невозможна без правки исходников Horizon (запрещено D-002).
- **Предложение техлид:** Kiln запускает `java kiln.Host` отдельным процессом и общается с ним строками через stdin/stdout. Игра никогда не ждёт Java. Проверено в настоящей игре: Java-мод из jar пишет строку на HUD Horizon (PROTON.md, «Результаты спайка»).
- **Альтернативы:** свой интерпретатор байткода на Rust внутри игры (недели работы, стандартную библиотеку Java писать самим); компилятор jar → Rust (ещё дольше); правка Horizon ради `unsafe` (это форк — против D-002).
- **Кто:** техлид предложил, владелец утвердил.

### D-020. Папка Kiln у игрока
- `<папка игры>/kiln/kiln-runtime.jar` — Java-классы Kiln; `<папка игры>/kiln/mods/*.jar` — Java-моды; `<папка игры>/kiln/java.log` — вывод Java. Настройка `java_home` (файл в `horizon-mods/.horizon-mod-data/kiln/`) выбирает Java вручную; иначе Kiln берёт самую новую Java 21+ из `KILN_JAVA_HOME`, `JAVA_HOME`, рантаймов лаунчера Minecraft и системных JDK.
- **Кто:** техлид.

### D-021. Моды под 26.3 требуют Java 25
- Шаблон Fabric для 26.3 компилирует моды под Java 25 (`release = 25`). Kiln должен запускать Java 25 или новее, иначе мод не загрузится (`UnsupportedClassVersionError`, Kiln сообщит в чат). Сейчас Kiln выбирает самую новую найденную Java; требование 25+ для модов добавим вместе с проверкой версии классов.
- **Кто:** техлид.

### D-022. Ядро таймера — чистая Java без классов Майнкрафта
- `mods/kiln-timer/src/main/java/.../core/`: состояния, сплиты, RTA/IGT, PB, строки HUD. Игра только сообщает события («новый мир», «измерение», «достижение», «пауза/загрузка»). Ядро покрыто JUnit-тестами (`./gradlew test`), игра для них не нужна.
- IGT — реальное время минус паузы и загрузки (D-012): игра сообщает «остановлено / идёт».
- **Кто:** техлид.

### D-017. Лицензия MIT, без файлов Mojang
- В репозитории нет кода, ассетов и файлов Mojang. Заглушки классов Майнкрафта — наш код с теми же именами классов и методов.
- **Кто:** из ТЗ.
